O **`jhonny-v`** é o ecossistema de infraestrutura, orquestração e ferramentas de uma **IA Pessoal de Alta Autonomia**. O sistema foi desenvolvido para atuar na gestão de tarefas diárias (Google Calendar, Gmail), gerenciamento de arquivos locais e assistência de desenvolvimento integrada ao VS Code, com suporte a execuções síncronas e em segundo plano via filas de mensagens.

---

## 📐 1. Descrição & Escopo

O projeto adota uma arquitetura descentralizada orientada a microsserviços e contêineres, unificando interfaces de conversação, proxy de modelos de linguagem, orquestrador de estado e servidor de ferramentas customizadas sob uma robusta stack de observabilidade.

## 🛠️ 2. Ambiente de Desenvolvimento

### Pré-requisitos
* **Docker Engine** (v24.0+) e **Docker Compose** (v2.20+)
* **Python** 3.11+ ou **Node.js** LTS (a depender do subrepo em `apps/`)
* **Git** 2.40+

### Variáveis de Ambiente
Copie o arquivo de exemplo na raiz do repositório e preencha as credenciais necessárias:

```bash
cp .env.example .env
```

O [`.env.example`](./.env.example) é a fonte de referência para todas as variáveis disponíveis. Os valores fornecidos são adequados apenas para desenvolvimento local e devem ser substituídos em outros ambientes.

Senhas e chaves são declaradas como Docker Compose Secrets. O Compose lê os valores do ambiente do host ou do arquivo `.env` e os monta somente nos serviços consumidores em `/run/secrets`; não declare essas credenciais diretamente em `services.*.environment`.

### 🚀 3. Subindo a Aplicação & Testes

### Executando a Stack de Observabilidade da Issue #104

O arquivo `infra/docker-compose.yml` contém apenas os recursos compartilhados. Para iniciar Prometheus, Grafana e Loki, combine-o com o arquivo de observabilidade e ative o profile da issue:

```powershell
# Inicie Prometheus, Grafana e Loki
docker compose `
  -f infra/docker-compose.yml `
  -f infra/docker-compose.obs.yml `
  --profile issue-104 `
  up -d

# Verifique o estado dos serviços
docker compose `
  -f infra/docker-compose.yml `
  -f infra/docker-compose.obs.yml `
  --profile issue-104 `
  ps
```

Após a inicialização, acesse o Grafana em `http://localhost:3000` e o Prometheus em `http://localhost:9090`.

### Executando a Stack Implementada da Milestone v0.1

Crie o arquivo local de ambiente antes da primeira execução:

```powershell
Copy-Item .env.example .env
```

Revise as credenciais de desenvolvimento em `.env` e execute:

```powershell
docker compose `
  --env-file .env `
  -f infra/docker-compose.yml `
  -f infra/docker-compose.core.yml `
  -f infra/docker-compose.llm.yml `
  -f infra/docker-compose.obs.yml `
  --profile v0.1 `
  up -d

# Verifica o status dos contêineres ativos
docker compose `
  --env-file .env `
  -f infra/docker-compose.yml `
  -f infra/docker-compose.core.yml `
  -f infra/docker-compose.llm.yml `
  -f infra/docker-compose.obs.yml `
  --profile v0.1 `
  ps
```

### Profiles completos por ambiente

Para habilitar métricas do host e do hardware, inclua também `infra/docker-compose.metrics.yml` e use um profile compatível:

| Ambiente | Profile | Fragment adicional |
| :--- | :--- | :--- |
| Docker Engine em Linux | `full-cloud-linux` | Nenhum |
| Linux com NVIDIA | `full-cloud-linux-nvidia` | Nenhum |
| Linux com AMD ROCm | `full-cloud-linux-amd` | Nenhum |
| Linux com GPU Intel | `full-cloud-linux-intel` | Nenhum |
| Windows residencial | `full-windows` | `infra/docker-compose.metrics.windows.yml` |
| Mac Mini M4 | `full-macos-m4` | `infra/docker-compose.metrics.macos.yml` |

Windows requer `windows_exporter` no host. No macOS, execute `infra/exporters/host-native/exporter.py` no host para coletar CPU, memória, disco, rede e processos pelas APIs usadas pelo Activity Monitor. Os comandos completos e pré-requisitos de GPU estão na [Issue #108](./docs/issues/v0.1/ISSUE-108.md).

Para rodar aplicações individualmente em modo de desenvolvimento local:

```Bash
# Executando o MCP Server
cd apps/mcp-server
pip install -r requirements.txt

# Executando o Agent Orchestrator
cd apps/agent-orchestrator

```


## 📊 4. Logs & Observabilidade

Toda a infraestrutura e aplicações do `jhonny-v` foram desenhadas com observabilidade nativa. Todos os logs de aplicações são obrigatoriamente direcionados para `stdout` e `stderr`.

### Pipeline de Telemetria

1. **Promtail**: Coleta logs dos contêineres (`stdout`/`stderr`) e os despacha para o Loki.
2. **Loki**: Indexa os logs das aplicações para consulta agregada.
3. **Prometheus**: Coleta métricas de desempenho do LiteLLM, LangGraph e contêineres.
4. **Grafana Tempo**: Processa e armazena distributed traces (OpenTelemetry / Spans do LangGraph).
5. **Grafana**: Painel único unificado.

### Acessos à Stack de Observabilidade

| Serviço | URL de Acesso Interna / Local | Credenciais Padrão |
| :--- | :--- | :--- |
| Grafana | `http://localhost:3000` | `admin` / valor de `GRAFANA_PASSWORD` |
| Prometheus | `http://localhost:9090` | Sem autenticação |
| Loki | `http://localhost:3100` | Interno (Push via Promtail) |
| Tempo (Jaeger GUI compatible) | `http://localhost:3200` | Visualização via Grafana Datasource |

### Dashboards compatíveis

O provisionamento padrão contém somente o dashboard interno `Jhonny Core - Visão Global`, compatível com Grafana `10.2.2` e com os UIDs fixos `prometheus`, `loki` e `tempo`. As variáveis `job` e `instance` são obtidas dos labels coletados, sem seleção manual de datasource.

Os painéis de Docker, host, contêineres, Tempo e GPU exibem dados apenas quando seus serviços ou exporters estão ativos. GPU requer um profile `metrics-gpu-*`; CPU por contêiner requer `metrics-containers` ou `full-cloud-linux*`. Na ausência dessas dependências, o painel vazio é esperado e não indica falha da stack base. Dashboards de LiteLLM, FastAPI e Ollama não são provisionados enquanto não houver um contrato estável de métricas.

Para auditar arquivos, queries e dependências sem iniciar a stack:

```bash
python infra/grafana/validation/validate_dashboards.py
```

O inventário completo, os probes por painel e a execução do profile `issue-109` estão documentados em [`docs/issues/v0.1/ISSUE-109.md`](docs/issues/v0.1/ISSUE-109.md).

### Exemplos de Log Queries (LogQL) no Grafana

Para filtrar logs específicos no Grafana Explorer (`http://localhost:3000/explore`):

- Logs do MCP Server:
  ```logql
  {container_name=~".*mcp-server.*"} |= "ERROR"
  ```
- Logs do Agent Orchestrator (LangGraph):
  ```logql
  {container_name=~".*agent-orchestrator.*"}
  ```
- Logs de Chamadas do LiteLLM Proxy:
  ```logql
  {container_name=~".*litellm.*"}
  ```
