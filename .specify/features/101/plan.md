# Implementation Plan: ISSUE-101 - Estrutura Base do Monorepo e Documentação Inicial

**Branch**: `101-monorepo-base-structure` | **Date**: 2026-10-01 | **Spec**: `ISSUE-101.SPEC.md`

**Input**: Feature specification from `ISSUE-101.SPEC.md` com clarificações integradas (5/5 questões respondidas)

---

## Summary

Criar a infraestrutura fundamental do monorepo com:
- Estrutura de diretórios padronizada (`apps/`, `infra/`, `docs/` com sub-pastas)
- Configuração de ambiente centralizada (`.env.example` sem prefix global)
- Segurança Git (`.gitignore` abrangente + pre-commit hooks com husky)
- Serviços core containerizados (PostgreSQL 15, Redis 7, RabbitMQ 3.12) orquestrados via Docker Compose
- Documentação estruturada com ADRs em formato MADR

---

## Technical Context

**Language/Version**: Monorepo polyglot (Python 3.11+, Node.js 18+, Docker Compose 2.0+)

**Primary Dependencies**: 
- Docker Engine 24.0+
- Docker Compose 2.0+
- Git 2.30+
- husky (pre-commit hooks)
- Node.js 18+ (para tooling / husky)

**Storage**: 
- PostgreSQL 15 (primary database)
- Redis 7 (cache + sessions + pub/sub)
- RabbitMQ 3.12 (message broker)

**Testing**: N/A (infra setup — validação via docker health checks + git status)

**Target Platform**: Linux, macOS (Intel/ARM), WSL2 (Windows)

**Project Type**: Monorepo infrastructure / orchestration

**Performance Goals**: 
- Dev environment startup: < 30 seconds
- Health check all services: < 5 seconds
- No service degradation under typical dev workload

**Constraints**: 
- All config via environment variables (12-factor)
- No hardcoded secrets in `.env.example`
- Pre-commit hooks must not block commits > 5 seconds

**Scale/Scope**: 
- Initial: 1 primary monorepo with 3 core services (DB, cache, broker)
- Extensible to multiple apps in `apps/` later (v0.2+)

**Structure Decision**: 
Monorepo padrão com separação clara entre:
- `apps/` — Aplicações (backend, workers, etc.)
- `infra/` — Configuração de container & orquestração
- `docs/` — Documentação centralizada com subdomínios (ADRs, issues, roadmap)
- `libs/` — Bibliotecas compartilhadas
- Dotfiles na raiz — Configuração global (`.env.example`, `.gitignore`, `.husky`)

## Phase 0: Research & Unknowns Resolution

### Research Tasks

| Unknown | Status | Finding |
|---------|--------|---------|
| Husky + Node.js setup em monorepo | ✅ RESEARCHED | Husky é padrão para pre-commit; requer Node.js 16+ e package.json na raiz |
| PostgreSQL 15 health check endpoint | ✅ RESEARCHED | Usar `pg_isready` CLI (built-in); Docker Compose healthcheck: `["CMD-SHELL", "pg_isready -U postgres"]` |
| Redis 7 health check | ✅ RESEARCHED | Usar `redis-cli ping`; Docker Compose healthcheck: `["CMD", "redis-cli", "ping"]` |
| RabbitMQ 3.12 health check | ✅ RESEARCHED | Usar `/api/aliveness-test`; Docker Compose healthcheck com curl |
| .gitignore patterns para Python + Node + Docker | ✅ RESEARCHED | Usar patterns: `node_modules/`, `__pycache__/`, `*.pyc`, `docker-compose.override.yml`, `.env` (not `.env.example`) |
| MADR format specifics | ✅ RESEARCHED | MADR template: Status, Context, Decision, Consequences, Compliance — exemplo será criado |
| Env var naming sem prefix | ✅ RESEARCHED | Padrão: `SERVICE_HOST`, `SERVICE_PORT`, `SERVICE_CREDENTIAL` (ex: `DB_HOST`, `REDIS_URL`, `RABBITMQ_USER`) |

### Findings Summary

**research.md** será gerado com decisões consolidadas em Phase 1.

## Risk Assessment & Mitigation

| Risk | Severity | Mitigation |
|------|----------|-----------|
| Docker not installed | HIGH | Documentation links to installation guides; fallback: manual setup instructions |
| Pre-commit hooks slow down commits | MEDIUM | Validate hook performance; skip with `--no-verify` if needed (documented) |
| `.env.example` falls out of sync | MEDIUM | Husky hook validates on commit; CI/CD double-checks |
| Service port conflicts | MEDIUM | Use non-standard ports (5433 for PG instead of 5432); document in `.env.example` |
| MADR templates not followed | LOW | Template file provided; pre-commit hook can validate structure |
